# マイルストーン管理ルール

`docs/initial-plan/milestones.md` はプロジェクト全体の進捗を表す合意ドキュメント。
個別タスクとは別に、開発フロー全体で一貫した管理を行う。

## チェックの更新タイミング

1. **`[x]` への書き換えは、完了したタスクの PR 内に含める**
   - `/implement` Step 4 で本 PR のコミットに含める
   - `main` への直接コミットは禁止ルールのため、別 PR で `[x]` だけ更新するパターンは避ける
   - `[x]` が事実として有効になるのは「PR がマージされた瞬間」
2. **`/dev-complete` がマージ前の最終 gate**
   - マージ**前**に PR 差分を確認し、milestones 更新が含まれていない場合は本 PR に追加してから merge する
   - 3 ケースで判定: (a) 既存項目の `[x]` 更新、(b) 既存 Phase への新規項目追加、(c) 新 Phase 追加 or 対象外（skill / `.claude/` メタ作業等）
3. **1 PR が複数のマイルストーン項目に対応する場合** は、該当する全項目を同じ PR 内で `[x]` に更新する
4. **1 PR が 1 項目の一部のみを満たす場合** は `[x]` を入れず、項目を分割するかコメントで進捗を残すかをユーザーに確認する

> PR マージ前のローカル完了は「完了」とみなさない。PR が revert された場合は revert PR 内で該当項目を `[ ]` に戻す。

## マイルストーンの追加・編集

### 個別タスクの追加（柔軟）
- `/dev-start` や `/implement` 中に未掲載の作業が必要と判明した場合、該当 Phase へのタスク追加をユーザーに提案する

### Phase 構造の変更（ユーザー確認必須）
以下は Claude 単独で行わず、必ず提案 → ユーザー承認の流れを踏む:
- Phase 自体の追加・削除・並び替え
- Phase のゴール・目標時期の変更
- 既に完了済み（`[x]`）項目の文言変更・削除

### マイルストーンに該当しないタスク
skill / docs / `.claude/` 配下のメタ作業は `milestones.md` への追加対象外とする。

判断基準:
- 一般ユーザーや管理者から見た**機能**として現れるか? → Yes なら追加対象
- リリースノートに書く価値があるか? → Yes なら追加対象
